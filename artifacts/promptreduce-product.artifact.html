What it is

Compression where the tokens actually are

Most of an agent's bill is not what you type. Measured over 40 real Claude Code sessions and 19,311 model calls, 95.4% of billed input volume is context re-sent on every turn, and tool results are 45% of everything that enters a transcript. A typed prompt is 12%, with a median of 31 tokens.

A tool result that enters early in a long session is paid for hundreds of times, once per later turn. Shrinking it at the moment it enters is worth far more than shrinking anything the user writes.

promptreduce sits between the client and the API as a proxy on localhost. It parses each request, rewrites the content of tool result blocks with pure, deterministic transforms, and forwards the rest byte for byte. Streaming responses pass through untouched while the proxy reads the usage figures on the way by.

Because the same content always renders to the same bytes, the API's prompt cache keeps matching across turns. That constraint rules out timestamps, counters and model calls in the transform path, and it is what makes the proxy safe to leave on.

Usage

Three commands, one variable

1

Start the proxy

bun install
bun run proxy        # http://localhost:8788 -> https://api.anthropic.com
2

Point a client at it

Any client that honors the base URL works. A Claude Code subscription login passes straight through, bearer token and all.

export ANTHROPIC_BASE_URL=http://localhost:8788
claude

Or in Claude Code's settings, per project or globally:

{ "env": { "ANTHROPIC_BASE_URL": "http://localhost:8788" } }
3

See what it does

The extractor builds a private corpus from your own transcripts. The eval page compresses any result in front of you, runs the whole corpus, and shows the proxy's live statistics next to the API's exact usage numbers.

bun run extract      # ~/.promptreduce/corpus, never leaves the machine
bun run eval         # http://localhost:8789
How it works

Three levels, chosen per deployment

Level 0lossless

ANSI escape codes, carriage-return redraws from progress bars, trailing whitespace, runs of blank lines, rows of separators, and consecutive identical lines replaced by one line with a count. Nothing a terminal would have shown is lost.

Level 1structural, default

JSON is walked deeply: HTML string values such as email bodies become plain text, empty fields are dropped, and the one array of records that dominates a payload is rendered once as a table. Passing test lines collapse to a count, stack frames inside dependencies fold, whitespace-free blobs are cut. Past a line or character budget the head and tail are kept with any line that looks like an error, and a marker names the archived original. A result identical to an earlier one in the same request becomes a one-line pointer.

Level 2aggressive

Half the budgets, plus column-alignment spaces in shell output collapsed to one.

File reads are never touched, because their line numbers must survive for later edits. Error results are never touched either.

Benefits

What you get, and what you keep

Works with everything

Claude Code, the official SDKs, Cursor, Cline, Aider and Continue all read the same environment variable. One process serves all of them.

Cache-safe by construction

Every transform is a pure function of the content. A result renders to identical bytes on every request that carries it, so cached prefixes keep matching.

Fails open

Any error while rewriting forwards the original request. Other endpoints, including token counting, pass through byte for byte.

Nothing is lost

Truncated results end with the path of the archived original, addressed by content hash. A model that needs the dropped line can read the file.

Visible savings

The eval page shows before and after with exact counts from the API, and the proxy records the usage figures the API returned for every request.

Private by default

Runs on localhost. The corpus built from your transcripts and the archive of originals stay in your home directory and out of the repository.

Where the money goes

The bill is mostly cache, and half of the cache is rebuilds

Forty real Claude Code sessions, 19,487 model calls, priced at Claude Opus 5.5 list prices with the one-hour cache Claude Code uses. Cache writes on that TTL cost twice the input price.

Rebuilds are the surprise. Of all cache-write tokens, 82% were spent in 687 calls where at least half the context was written again from scratch. A third of those followed an idle gap of more than an hour, when the cache had expired. The rest came from anything that changes the cached prefix mid-session: an MCP server connecting late and enlarging the tool list, a system prompt that shifts, compaction.

Output is smaller than people expect, and it is not the prose. Visible text and tool inputs account for about 12% of billed output tokens. The other 88% is thinking. So the lever on output is the effort setting, which decides how much the model reasons and how many tool calls it makes, and a verbosity setting is a rounding error next to it.

Potential future

What comes next, and what each step is worth

Next · €170 to €260 per €1,000

Cache rebuild guard

Freeze the tool list and system prompt for the life of a session, keep an idle session's cache warm with a cheap read before it expires, and report every rebuild with its cost so the causes become visible.

Next · €150 to €300 per €1,000

Effort control

Effort per client, per project and per subagent, set at session start or through the per-message channel that does not reset the cache. Medium for routine work, low for exploration, the default kept for the hard parts.

Next · €5 to €15 per €1,000

Verbosity setting

A terse, normal or full setting that appends a short system message each turn. Small on the bill, large on how much you have to read.

Next · €50 to €230 per €1,000

Tool-definition slimming

An explicit allow list of tools per project. On a machine with many MCP servers the definitions alone are the largest single cost line.

Later · €80 to €150 per €1,000

Eviction of stale results from history

Stub results that have served their purpose, batched so one cache rebuild buys many cheap turns.

Later · €60 to €80 per €1,000

Long-result summarization

A small model condenses the long tail, memoized by content hash so the summary is the same bytes on every request.

Later · €125 to €200 per €1,000

Model routing for subagents

Bulk and exploratory work on a cheaper model while the main thread keeps the strongest one.

Later

A fidelity eval, an OpenAI-compatible endpoint, profiles and a CI gate

An LLM judge that measures what the model lost for every transform, the same treatment for clients that speak the chat completions format, per-project profiles, and a check that fails a change when corpus savings regress.

Known limits today

Token numbers inside the proxy are estimates; exact counts come from the API's count_tokens endpoint through the eval page. The tools array and the system prompt are never edited. Summarization and history eviction are not built yet, because both change bytes inside the cached prefix and need a batching policy before they save money instead of costing it.
